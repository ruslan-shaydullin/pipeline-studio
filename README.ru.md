# Pipeline Studio

[English](README.md) · Русский

Локальная веб-среда для повторяемых джоб из отдельных сессий Codex.

## Запуск

Нужны Node.js 22.13+ и Codex CLI, авторизованный через `codex login`. Если установлен ChatGPT/Codex desktop, по умолчанию используется его встроенный CLI; иначе — `codex` из PATH. Для явного выбора задайте `PIPELINE_CODEX_BIN`.

```sh
npm ci
npm run dev
```

Открыть [localhost:3000](http://localhost:3000). Команда запускает веб-интерфейс и локальный исполнитель на `127.0.0.1:4317`. Остановка процесса через Ctrl+C останавливает оба сервиса. Закрытие вкладки не останавливает запущенную работу.

Для самостоятельного запуска частей есть `npm run dev:web` и `npm run dev:runner`. Переменная `PIPELINE_CODEX_BIN` задаёт путь к другому Codex CLI. `PIPELINE_DATA_DIR` позволяет сменить каталог данных. Смена `PIPELINE_PORT` требует соответствующей настройки proxy в `vite.config.ts`.

## Первый настоящий запуск

Откройте джобу **«Исправить issue»** и нажмите **«Новый запуск»**. В форме уже выбрана папка `examples/issue-lab`: небольшой проект без зависимостей с ошибкой и тремя падающими тестами.

1. **Разбор задачи** — отдельная сессия исследует код и запускает тесты.
2. **Выполнение** — новая сессия получает результаты разбора и копию файлов, исправляет код.
3. **Проверка** — ещё одна сессия независимо проверяет результат.

Нажатие на круг этапа открывает его диалог. В процессе можно отправить уточнение (⌘ Enter), посмотреть команды и их вывод, изменения файлов, вход и переданный результат. В режиме с подтверждениями запросы технических разрешений показываются в сессии; разрешение действует один раз. Режим можно выбрать для всей джобы.

Сессия занимает основную рабочую область. Кнопка разворачивания справа вверху скрывает общую навигацию; повторное нажатие возвращает её. История запусков открывается через «Запуск N». Завершённая сессия показывает компактный итог вместо отключённого поля ввода.

В открытой вкладке сохраняются черновики сообщений для каждой попытки, выбранные попытки и позиции прокрутки при переключении этапов, джоб и конструктора. После перезагрузки страницы черновики сообщений исчезают. Изменения в самих джобах сохраняются автоматически на диск.

**«Повторить отсюда»** позволяет исправить инструкцию и создать новую попытку этапа. Последующие этапы выполняются заново; старые сессии и их файлы остаются в истории. Изменение джобы в конструкторе влияет на будущие запуски, а инструкция повтора — только на этот запуск.

Вместо учебной папки можно указать абсолютный путь к своему проекту и описание задачи или issue. Агент начинает работу с копией. В режиме полного доступа песочница не защищает исходную папку от записи.

## Продолжение готового результата

После завершения запуска доступна кнопка **«Продолжить»**, даже если новых этапов в шаблоне ещё нет. Можно взять добавленные в джобу этапы или описать самостоятельный следующий шаг прямо в окне продолжения. Ручной шаг относится только к этому запуску и не меняет шаблон. В окне выберите готовый запуск: зелёные строки показывают этапы, результат которых будет использован, ниже — новые инструкции. Первый этап заново не выполняется. Следующая сессия получает прежнюю задачу запуска, отчёты, переданный контекст и копию файлов последнего завершённого этапа.

В этом окне можно уточнить промпты новых этапов только для продолжения. Для второго этапа пишите действие — например, «Сравни найденных кандидатов по сложности, активности проекта и наличию конкурирующих PR, выбери одного и обоснуй выбор». Вставлять результат поиска в промпт вручную не требуется.

**«Новый запуск» → «Запустить с начала»** явно начинает все шаги заново. **«Повторить отсюда»** повторно выполняет выбранный существующий этап и последующие. Продолжение добавляет новые шаги к тому же запуску и сохраняет прежние сессии.

Если промпты или настройки готовых этапов изменились, окно предупреждает, что используются их прежние результаты. При перестановке или удалении этапов можно продолжить результат самостоятельным ручным шагом. Чтобы применить новые инструкции к уже выполненной работе, используйте повтор с затронутого этапа. Созданные агентом шаги также сохраняются; новые фиксированные этапы добавляются после всего выполненного плана. Повтор отправки одного запроса продолжения не создаёт дубли сессий.

## Помощник по пайплайну

Откройте **«Помощник»**, опишите конечную цель и нажмите **«Глубоко проверить»**. Отдельная сессия Codex с высоким усилием рассуждения получает все промпты и сводки до трёх последних запусков. Она проверяет, доводит ли план до цели, где теряется контекст, какие шаги отсутствуют или дублируются, как проверить результат и что требуется для публикации.

Помощник показывает замечания с конкретными основаниями, неясные требования и цельный улучшенный пайплайн. Каждый предложенный этап раскрывается: видны причина изменения, полный новый промпт и прежняя инструкция. **«Применить к джобе»** сохраняет предложенный шаблон, **«Отменить применение»** возвращает предыдущий. Запуски и права доступа сохраняются; применение не запускает агентов. Если джобу успели отредактировать, устаревшее применение или отмена не затрут эти правки.

Разбор изучает переданные инструкции и сводки результатов; код репозитория и актуальность внешних фактов он не проверяет. Работает в режиме чтения без сети, использует лимиты аккаунта Codex и останавливается отдельно от выполнения этапов. Закрытие окна не прерывает разбор. Последние 20 разборов сохраняются локально; после перезапуска исполнителя незавершённый анализ нужно запустить заново. Длинные поля истории сокращаются, слишком большой вход отклоняется с объяснением.

## Доступ пайплайна

Кнопка **«Доступ»** в шапке задаёт режим для всей джобы, включая этапы, созданные агентом. Настройка сохраняется на диск, переносится при экспорте и импорте. Перед запуском её можно изменить только для этой итерации.

| Режим | Файлы | Сеть | Подтверждения |
| --- | --- | --- | --- |
| С подтверждениями (по умолчанию) | Запись в рабочую папку | По запросу | Для расширения доступа |
| Рабочая папка + сеть | Запись в рабочую папку | Разрешена | Для действий за пределами песочницы |
| Полный доступ | Без ограничений песочницы | Разрешена | Технические разрешения не запрашиваются |

Рабочие режимы ограничивают запись, а не все операции чтения: Codex может читать доступные ему файлы по своей политике. Полный доступ действует с правами пользователя ОС: агент получает доступ к файлам компьютера и сети, включая данные вне копии проекта. Выбирайте его для задач и промптов, которым доверяете. Системная политика Codex может дополнительно ограничить доступ.

Запуск хранит собственную копию режима. Правка джобы не меняет выполняющуюся сессию. При продолжении готового результата режим явно выбирается для новых этапов; прежние попытки сохраняют свою историю доступа. Вопросы по требованиям (`needs_input` и запросы ответа) остаются во всех режимах. Техническое разрешение не означает разрешения расширить задачу.

## Что сохраняется

- Проекты, папки и шаблоны джоб — в `.pipeline-data/workspace.json`. Запись атомарная, предыдущая версия хранится в `.bak`. При повреждении основного файла исполнитель восстанавливает резервную копию и показывает уведомление.
- При первом подключении прежние джобы автоматически переносятся из localStorage. Исходные данные браузера сохраняются. Если сервер уже содержит джобы, перенос доступен отдельно через меню данных.
- Запуски, инструкции каждой попытки, сообщения, действия, результаты и идентификаторы сессий — в `.pipeline-data/runs.json`.
- Разборы помощника, предложения и исходные шаблоны для отмены — в `.pipeline-data/reviews.json`.
- Отдельные рабочие папки попыток — в `.pipeline-data/workspaces/<run>/<attempt>`.
- Авторизацией управляет установленный Codex CLI. Приложение не копирует и не читает OAuth-токены.

Путь к файлам выбранной попытки доступен в разделе **«Изменения»**. Перед следующим этапом передаются завершённые результаты предыдущих этапов и копия рабочей папки. При перезапуске исполнителя незавершённые сессии отмечаются остановленными; они не запускаются повторно автоматически. Их можно явно продолжить сообщением либо повторить этап.

Меню **«Джобы и данные»** в правом верхнем углу показывает состояние сохранения и позволяет экспортировать или импортировать JSON. Экспорт содержит проекты, папки и промпты, без сессий и рабочих файлов. Импорт добавляет отсутствующие джобы; изменённые копии сохраняет отдельно. Повторный импорт идентичного файла не дублирует джобы.

При одновременном редактировании в нескольких вкладках приложение обнаруживает конфликт: можно сохранить свои изменения отдельными копиями либо загрузить серверную версию. До успешной записи правки остаются в открытой вкладке и, если доступен localStorage, в локальном черновике этой вкладки. Ошибка записи не показывается как успешное сохранение.

## Этапы, которые создают этапы

В конструкторе выберите этап → **«Промпт» → «Может создавать этапы»**. Такой агент возвращает от нуля до пяти новых шагов с названиями и самостоятельными промптами. Они вставляются сразу после него, перед оставшимися фиксированными этапами, и выполняются в отдельных сессиях Codex. Общий лимит — 50 этапов; при приближении к нему доступное число новых шагов уменьшается. Ветвление и параллельное исполнение пока не поддерживаются.

Этапы добавляются только после успешного `done`. При `needs_input` агент ждёт ответа и может сформировать план после продолжения. Созданные этапы отмечены значком искр; сами создавать новые этапы они не могут. Изменения относятся только к конкретному запуску — шаблон джобы сохраняется.

При повторе планировщика его предыдущие созданные этапы уходят в **«Предыдущие планы»** вместе с перепиской, попытками и файлами. Повтор отдельного созданного этапа сохраняет текущий порядок шагов. В контексте планировщика доступны ссылки на созданные им этапы, включая архивные.

Чтобы повторять удачный план, откройте **«История запусков» → «Сохранить план как джобу»**. Получится отдельная джоба с фиксированными шагами; инструкция планировщика заменяется подготовкой контекста для выбранных шагов. Названия и промпты можно поправить перед следующим запуском.

## Границы первой версии

- Один выполняющийся агент одновременно; новые запуски ждут в очереди. Ожидание ответа после завершённого хода не мешает другим запускам.
- Реальный исполнитель — Codex. Claude Code ещё не подключён. Используются лимиты текущего аккаунта Codex; модель можно выбрать в форме запуска.
- Сервер принимает запросы только с ноутбука. Это локальный инструмент для одного пользователя, без многопользовательской авторизации.
- При копировании исходников исключаются `.git`, зависимости, каталоги сборки, локальные `.env`, ключевые файлы и символические ссылки. Лимит копии: 10 000 файлов / 150 МБ.
- Между этапами сохраняются созданные артефакты, в том числе `dist` и `coverage`; `.git`, `node_modules` и символические ссылки не переносятся. Зависимости при необходимости нужно установить в рабочей папке этапа.
- Доступ определяется режимом запуска. Push, PR, публикации и сообщения допустимы только когда явно поручены в задаче или этапе; отдельного редактора таких действий пока нет.
- Формат результата поддерживает `done`, `needs_input`, `failed`, `skipped`. Условия переходов через отдельный визуальный редактор ещё не добавлены.
- Одновременно выполняется один разбор помощника, независимо от очереди этапов. Запуски и рабочие папки не удаляются автоматически.

## Архитектура

React 19 / TypeScript / Vinext / Tailwind / Base UI. Круглый конструктор сохранён. Интерфейс отправляет команды по REST и получает состояния через SSE; Vite проксирует `/api/runner` на локальный Node-процесс. Тот общается с `codex app-server` по JSONL/stdio. Каждая попытка этапа получает отдельный Codex thread, продолжение — следующий turn той же сессии.

Адаптер проверен на `codex-cli 0.153.4`. Codex app-server использует развивающийся протокол; после обновления CLI интеграцию следует перепроверить.

Этот исполнитель требует локального Node-процесса. Обычная сборка фронтенда для Cloudflare Workers сама по себе не запускает Codex; публикация продукта в веб здесь не настроена.

## Проверки

```sh
npm run test:runner
npx tsc --noEmit
npm run lint
npm run build
```

Тесты хранения проверяют миграцию, импорт, конфликты вкладок, восстановление резервной копии, повтор после сетевых ошибок и правки во время сохранения. Тесты динамического плана проверяют вставку этапов, отдельные сессии, запрет рекурсии, лимиты, архивирование и защиту от повторного применения результата.

Тесты помощника проверяют применение и отмену, конфликты правок, идемпотентность, остановку, тайм-аут, ошибки сохранения и валидацию предложений.

Тесты исполнителя проверяют последовательность сессий, дубли завершения, ошибки результата, ожидание ответа, steer/resume, разрешения, stop, повтор и сохранение истории, перезапуск, гонки stop/retry/resume и передачу артефактов.
