# Руководство пользователя Pipeline Studio

[English](user-guide.md) · Русский · [К README](../README.ru.md)

Pipeline Studio — локальная среда для одного пользователя, в которой повторяемые задачи выполняются отдельными сессиями Codex. **Джоба** — это повторяемый шаблон. **Запуск** хранит собственную задачу, этапы и историю выполнения. Каждый новый этап или повтор получает отдельную **попытку**, рабочую папку и сессию Codex; возобновление существующей попытки сообщением сохраняет её сессию и файлы.

## Установка и выбор CLI

Нужны **Node.js 22.13+**, npm, Git и авторизованный [Codex CLI](https://developers.openai.com/codex/cli). Адаптер проверен с `codex-cli 0.153.4`. Основная проверенная платформа — macOS; CI на Linux проверяет установку, тесты и сборку. Другие платформы и версии CLI могут потребовать доработки интеграции.

```sh
git clone https://github.com/ruslan-shaydullin/pipeline-studio.git
cd pipeline-studio
npm ci
codex login
npm run dev
```

Откройте [localhost:3000](http://localhost:3000). `npm run dev` запускает интерфейс на `localhost:3000` и исполнитель на `127.0.0.1:4317`; `npm start` — псевдоним для той же среды разработки. Ctrl+C останавливает оба сервиса. Закрытие вкладки не останавливает запуск. Части также можно запустить отдельно командами `npm run dev:web` и `npm run dev:runner`.

Если `PIPELINE_CODEX_BIN` не задан, исполнитель проверяет `/Applications/ChatGPT.app/Contents/Resources/codex`, затем использует `codex` из `PATH`. Другой путь к встроенному CLI нужно явно указать через `PIPELINE_CODEX_BIN`. Чтобы явно выбрать CLI из терминала:

```sh
PIPELINE_CODEX_BIN="$(command -v codex)" npm run dev
```

Авторизуйтесь тем исполняемым файлом, который использует исполнитель. Авторизацией управляет Codex CLI: приложение не копирует и не читает OAuth-токены и не передаёт API-ключ во фронтенд. Запуски используют лимиты текущего аккаунта. Модель можно выбрать в форме запуска.

| Переменная           | Назначение                                                             |
| -------------------- | ---------------------------------------------------------------------- |
| `PIPELINE_CODEX_BIN` | Путь к исполняемому файлу Codex                                        |
| `PIPELINE_DATA_DIR`  | Каталог данных; по умолчанию `.pipeline-data`                          |
| `PIPELINE_PORT`      | Порт исполнителя; изменение требует настройки proxy в `vite.config.ts` |

Оставляйте исполнитель локальным. Он принимает запросы только с вашего компьютера, не имеет многопользовательской авторизации и не предназначен для доступа из сети.

## Запуск пайплайна и работа с сессией

Откройте **«Исправить issue» → «Новый запуск»**. В форме выбрана папка [`examples/issue-lab`](../examples/issue-lab): небольшой проект без зависимостей с ошибкой и тремя падающими тестами. Исходник намеренно оставлен сломанным, чтобы каждый запуск исправлял свою копию.

1. **«Разбор задачи»** — отдельная сессия исследует код и запускает тесты.
2. **«Выполнение»** — новая сессия получает результаты разбора и копию файлов, исправляет код.
3. **«Проверка»** — ещё одна сессия независимо проверяет результат.

Для своей задачи укажите абсолютный путь к проекту и описание задачи или issue либо начните без файлов. Каждый этап работает в отдельной копии и получает завершённые результаты предыдущих этапов, переданный контекст и файлы. В режиме полного доступа сессия может записывать данные вне копии; см. [режимы доступа](#режимы-доступа).

Нажмите на круг этапа, чтобы открыть его сессию. Можно посмотреть команды и вывод, изменения файлов, вход и переданный результат. Отправляйте уточнения сочетанием **⌘ Enter**. Если выбранный режим требует технического подтверждения, запрос появится в сессии; разрешение действует один раз.

Сессия занимает основную рабочую область. Кнопка разворачивания справа вверху скрывает навигацию; повторное нажатие возвращает её. История запусков открывается через **«Запуск N»**. Завершённая сессия показывает компактный итог вместо отключённого поля ввода.

В открытой вкладке сохраняются черновики сообщений каждой попытки, выбранные попытки и позиции прокрутки при переключении этапов, джоб и конструктора. После перезагрузки страницы черновики сообщений исчезают. Изменения в джобах сохраняются автоматически на диск.

## Продолжение, повтор и новый запуск

| Действие                                  | Результат                                                                                                                          |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| **«Новый запуск» → «Запустить с начала»** | Новый запуск всех этапов с начала                                                                                                  |
| **«Повторить отсюда»**                    | Новая попытка выбранного этапа и повтор последующих                                                                                |
| Отправка сообщения                        | Уточнение активного хода или возобновление ожидающей, завершившейся ошибкой либо остановленной попытки с прежней сессией и файлами |
| **«Продолжить»** после завершения         | Использование готовых результатов и добавление новых этапов к тому же запуску                                                      |

При повторе можно изменить инструкцию только для этого запуска. Прежние попытки, сессии и файлы остаются доступны. Правка джобы в конструкторе влияет на будущую работу и не переписывает завершённые попытки.

Кнопка **«Продолжить»** доступна, даже если новых этапов в шаблоне ещё нет. Выберите готовый запуск в окне продолжения, затем возьмите добавленные в джобу этапы или опишите самостоятельный следующий шаг. Ручной шаг относится только к этому запуску и не меняет шаблон. Зелёные строки показывают результаты, которые будут использованы, ниже находятся новые инструкции. Первый этап заново не выполняется.

Новые промпты можно уточнить только для этого продолжения. Описывайте действие, например: «Сравни найденных кандидатов по сложности, активности проекта и наличию конкурирующих PR, выбери одного и обоснуй выбор». Вставлять прежний результат поиска в промпт вручную не требуется. Новые сессии получают исходную задачу запуска, предыдущие отчёты и переданный контекст, а также копию файлов последнего завершённого этапа.

Если промпты или настройки готовых этапов изменились, окно предупреждает, что используются прежние результаты. Чтобы применить новые инструкции к выполненной работе, повторите запуск с затронутого этапа. После перестановки или удаления этапов можно продолжить результат ручным шагом. Созданные агентом этапы сохраняются в запуске; новые фиксированные этапы добавляются после выполненного плана. Повтор отправки одного запроса продолжения не создаёт дубли сессий.

В окне продолжения выберите режим доступа для новых этапов. Прежние попытки сохраняют исходную историю доступа.

## Помощник по пайплайну

Откройте **«Помощник»**, опишите конечную цель и нажмите **«Глубоко проверить»**. Отдельная сессия Codex с высоким усилием рассуждения получает все промпты этапов и сводки до трёх последних запусков. Она проверяет, доводит ли план до цели, какие шаги отсутствуют или дублируются, как передаётся контекст, как проверить завершение, где создаются новые этапы и что требуется для публикации.

Разбор показывает замечания с конкретными основаниями, неясные требования и цельный предложенный пайплайн. Раскройте этап, чтобы увидеть причину изменения, полный новый промпт и прежнюю инструкцию. **«Применить к джобе»** сохраняет предложенный шаблон; **«Отменить применение»** возвращает предыдущий. Ни одно из действий не запускает агентов и не меняет права доступа. Если после анализа или применения джобу отредактировали, устаревшее применение или отмена будут отклонены, сохраняя эти правки.

Помощник изучает переданные инструкции и сводки результатов; код репозитория и актуальность внешних фактов он не проверяет. Он работает в режиме чтения без сети и использует лимиты аккаунта Codex. Один разбор может выполняться одновременно с этапами пайплайна. Его можно остановить отдельно; закрытие окна не прерывает анализ.

Последние 20 разборов сохраняются локально. После перезапуска исполнителя незавершённый анализ нужно запустить заново явно. Длинные поля истории сокращаются; слишком большой вход отклоняется с объяснением.

## Режимы доступа

Кнопка **«Доступ»** в шапке задаёт режим джобы по умолчанию. Его наследуют все этапы, включая созданные агентом. Настройка сохраняется на диск и переносится при экспорте/импорте шаблона. Перед запуском её можно изменить только для этого запуска.

| Режим                                | Запись                          | Сеть       | Технические подтверждения           |
| ------------------------------------ | ------------------------------- | ---------- | ----------------------------------- |
| **С подтверждениями** (по умолчанию) | В рабочую папку                 | По запросу | При необходимости                   |
| **Рабочая папка + сеть**             | В рабочую папку                 | Разрешена  | Для действий за пределами песочницы |
| **Полный доступ**                    | Без ограничений песочницы Codex | Разрешена  | Отключены                           |

Рабочие режимы ограничивают запись, а не все операции чтения: Codex может читать доступные ему файлы по своей политике. Полный доступ действует с правами пользователя ОС и позволяет обращаться к файлам вне рабочей копии. Выбирайте его для задач и промптов, которым доверяете. Политика компьютера или администратора может дополнительно ограничить выполнение.

Запуск хранит собственную копию режима. Правка джобы не меняет выполняющуюся сессию. Продолжение выбирает доступ для новых этапов, сохраняя прежние попытки. Вопросы по требованиям (`needs_input` и запросы ответа) остаются интерактивными во всех режимах. Отключение технических подтверждений не отвечает на бизнес-вопросы и не расширяет задачу. См. [протокол разрешений Codex](https://developers.openai.com/codex/app-server).

Push, PR, публикации и сообщения должны быть явно поручены в задаче или этапе. Отдельного редактора таких действий пока нет.

## Локальные данные, экспорт и восстановление

| Путь                                        | Содержимое                                                                                 |
| ------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `.pipeline-data/workspace.json`             | Проекты, папки и шаблоны джоб; атомарная запись с резервной копией `.bak`                  |
| `.pipeline-data/runs.json`                  | Запуски, инструкции попыток, сообщения, действия, результаты и идентификаторы сессий Codex |
| `.pipeline-data/reviews.json`               | Разборы помощника, предложения и исходные шаблоны для отмены                               |
| `.pipeline-data/workspaces/<run>/<attempt>` | Рабочие файлы каждой попытки                                                               |

Эти файлы исключены из Git. При повреждении `workspace.json` исполнитель восстанавливает резервную копию и показывает уведомление. Хранилища запусков и разборов сохраняют историю, но не имеют тех же гарантий восстановления из резервной копии, что и хранилище джоб.

При первом подключении прежние джобы автоматически переносятся из localStorage, не удаляя исходные данные браузера. Если на сервере уже есть джобы, перенос доступен отдельно через меню данных.

Раздел **«Изменения»** показывает папку выбранной попытки. После перезапуска исполнителя незавершённые сессии отмечаются остановленными и не запускаются автоматически. Возобновите нужную явно сообщением или повторите этап. Готовые результаты и рабочие файлы остаются доступны.

Откройте **«Джобы и данные»** справа вверху, чтобы увидеть состояние сохранения или экспортировать/импортировать JSON. Экспорт переносит проекты, папки и шаблоны джоб, без сессий и рабочих файлов. Импорт добавляет отсутствующие джобы и сохраняет изменённые версии отдельными копиями. Повторный импорт идентичного файла не дублирует джобы. При переносе на другой компьютер скопируйте весь каталог данных. Не размещайте большие рабочие папки в каталогах с облачной выгрузкой файлов.

При редактировании в нескольких вкладках приложение обнаруживает конфликт. Можно сохранить свои изменения отдельными копиями либо загрузить серверную версию. До успешной записи правки остаются в открытой вкладке и, если доступен localStorage, в локальном черновике этой вкладки. Ошибка записи не показывается как успешное сохранение.

## Копирование исходников и передача между этапами

Копирование исходников исключает метаданные Git, зависимости, кеши, результаты сборки, локальные `.env`, ключевые файлы и символические ссылки. Лимит копии — **10 000 файлов / 150 МБ**.

При передаче между этапами сохраняются созданные артефакты, в том числе `dist` и `coverage`, но исключаются `.git`, `node_modules` и символические ссылки. Каждая новая попытка получает новую локальную базу Git для сравнения изменений. При необходимости восстановите зависимости и контекст репозитория в рабочей папке этапа: исходная история Git и установленные пакеты не переносятся автоматически.

Механизм копирования не является границей безопасности в режиме полного доступа. Рабочие папки сохраняются, пока вы не удалите их самостоятельно.

## Этапы, которые создают этапы

В конструкторе выберите этап и откройте **«Промпт» → «Может создавать этапы»**. Планировщик может вернуть от нуля до пяти новых этапов с названиями и самостоятельными промптами. Они вставляются сразу после него, перед оставшимися фиксированными этапами, и выполняются в отдельных сессиях Codex. Общий лимит — 50 этапов; при приближении к нему доступное число новых шагов уменьшается.

Этапы вставляются только после успешного `done`. При `needs_input` агент ждёт ответа и может сформировать план после возобновления. Созданные этапы отмечены значком искр и сами создавать этапы не могут. Расширение относится только к запуску, шаблон джобы не меняется.

Повтор планировщика переносит его прежние созданные этапы в **«Предыдущие планы»**, сохраняя переписку, попытки и файлы. Повтор одного созданного этапа сохраняет текущий порядок. В контексте планировщика есть ссылки на созданные им этапы, включая архивные.

Чтобы использовать удачный план повторно, выберите **«История запусков» → «Сохранить план как джобу»**. Получится отдельная джоба с фиксированными этапами. Инструкция планировщика заменяется подготовкой контекста для этих этапов. При необходимости поправьте названия и промпты перед следующим запуском.

## Текущие ограничения

- Одновременно выполняется один этап пайплайна; дополнительные запуски ждут в очереди. Ожидание ответа после завершённого хода не мешает другим запускам. Один отдельный разбор помощника может идти одновременно с выполнением.
- Пайплайны линейные: ветвления, параллельных этапов и визуального редактора условий пока нет.
- Единственный подключённый исполнитель — Codex; Claude Code пока не интегрирован.
- Структурированный результат поддерживает `done`, `needs_input`, `failed` и `skipped`.
- Черновики сообщений относятся к открытой вкладке и исчезают при перезагрузке. Запуски и рабочие папки не удаляются автоматически.
- Это локальный инструмент для одного пользователя без многопользовательской авторизации и облачного исполнения.

## Разработка и архитектура

Интерфейс использует React 19, TypeScript, Vinext/Vite, Tailwind и Base UI, с круглым конструктором пайплайна. Он отправляет команды через REST и получает состояние через server-sent events (SSE). Vite проксирует `/api/runner` на локальный Node-процесс, который общается с `codex app-server` по JSONL/stdio. Новая попытка получает отдельный Codex thread; возобновление сообщением добавляет turn в ту же сессию, а продолжение завершённого запуска создаёт новые этапы с отдельными сессиями.

Протокол Codex app-server развивается; после обновления CLI интеграцию следует перепроверить. Каркас включает публичные плагины OpenAI Sites и Cloudflare, но локальный запуск не требует регистрации в Sites. `npm run build` проверяет фронтенд; его результат, в том числе сборка для Cloudflare Workers, сам по себе не запускает локальный исполнитель Codex. Облачное выполнение продукта не настроено.

```sh
npm run test:runner
npm run typecheck
npm run lint
npm run build
```

Тесты используют подставные клиенты Codex и временные каталоги: аккаунт, платные вызовы модели и личные джобы не нужны. CI запускает эти проверки. [`examples/issue-lab`](../examples/issue-lab) — намеренно сломанный учебный проект, который не входит в набор тестов приложения.

Тесты хранения проверяют миграцию, импорт, конфликты вкладок, восстановление резервной копии, повторы после сетевых ошибок и правки во время сохранения. Тесты планировщика проверяют вставку этапов, отдельные сессии, запрет рекурсии, лимиты, архивирование и защиту от повторных результатов. Тесты помощника покрывают применение и отмену, конфликты правок, идемпотентность, остановку, тайм-ауты, ошибки сохранения и валидацию предложений. Тесты исполнителя проверяют последовательность сессий, дубли завершения, ошибки результата, ожидание ответа, steer/resume, разрешения, stop/retry с сохранением истории, перезапуск, гонки жизненного цикла и передачу артефактов.
